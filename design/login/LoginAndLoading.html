Design round 1 · login and loading

A calmer sign-in, and something to watch while the numbers load

Everything below is live: pick a state, press the button, run a slow load, play the game. Nothing here is wired to the app yet. All figures are made up, and the wait screen never shows real data. My picks are marked pick; the open choices are at the bottom, each with a default.

1 · The sign-in page pick: The Cup

Same app colours and rings as the dashboards. One job: one button. The cup drops a coin in every 2.6 s (a CSS-only loop, so it also plays before any script, and the page is still a plain link without script). Use the list to see every state the page can be in.

1b · The cup, in five looks pick: Ceramic 3D

Fixed: the coins used to be cut by the top edge of the picture. They now start above it, small and faint, grow into view, fall with gravity, spin as they go, and slip behind the cup's own front lip before they disappear, with a ripple on the chai when they land. Move your pointer around the page: the cups tilt toward it (off with reduced motion, and on touch). Pick a look and it changes the sign-in page, the wait screen and the game's cup everywhere on this board.

2 · Every state at a glance

Thirteen states. The page is one HTML response built on the server, so each is a few lines of text and one class, never a different page.

3 · Phone, small phone, short screens

No text box means no on-screen keyboard to fight with, so the page only needs to survive narrow and short. Under 480 px tall (a phone on its side) the cup and the subtitle step aside so the button never scrolls off.

4 · The wait screen pick: Cup first, a game after 3 s

Today every page waits on Google Sheets and nothing is drawn while it does: a blank page for as long as the read takes. This is the screen for that wait, in the content area only, so the sidebar stays put and works. The timing rules matter more than the picture: run the buttons to see them.

5 · The two games

Both are one-thumb, endless, and have no game-over screen to dismiss, because the page can arrive any second. Best score is kept in this browser only (localStorage, wrapped in a try so private windows still play). Click or tap the board, then use the arrow keys, A/D, space or touch. Esc, or Tab, leaves it.

Coin catch pick

Slide the cup under the falling ₹. The red EMI slips cost you 3. Never ends; the score is “coins in the fund”.

Coin hop

One tap to jump the cardamom pods. Speeds up. A hit just restarts after a tap.

7 · The corner cases, and what each one does

Sign-in page

  1. Already signed in opens /login → straight on to the page. Today it shows the sign-in again.
  2. Double tap → the first tap locks the button (“Opening Google…”); one request only.
  3. Back button from Google → the browser may restore the frozen “Opening…” page; on pageshow it resets to idle.
  4. Google never answers (8 s) → “Try again”, button unlocked.
  5. Offline → button off with the reason; unlocks on its own when back online.
  6. Wrong Google account → “isn't allowed here”, and the button becomes “Choose another account” (asks Google to show the picker, or it silently reuses the same account). Never says which address would work.
  7. Cancel on Google → a calm line, nothing changed.
  8. Failed (second tab, 10-minute cookie ran out, cookies blocked) → one message plus a cookie hint; the page he was going to is kept when known.
  9. Session ended → “carry on to Cards”, the name taken from a fixed list of our pages, never the raw address (so a crafted link can't put words on the page).
  10. Just signed out → “You're signed out on this device. Other devices stay in.” Needs ?signedout=1 from /logout.

Sign-in page, continued

  1. Not set up → button off, a plain line. The names of the missing settings show only when running locally (a stranger shouldn't be told how it's built).
  2. Instagram, Facebook, LINE or any in-app browser → Google refuses sign-in there (“disallowed_useragent”). Spot it from the user agent and show “Open in Safari or Chrome” and Copy link, instead of a button that dead-ends.
  3. No JavaScript → still a normal link; the cup is CSS only. Only the lock, offline and in-app checks need script, and they degrade to the plain button.
  4. Odd addresses → ?error= shows only our three codes; next still goes through safeNextPath.
  5. Keyboard and screen readers → one button, visible focus ring, notices are role="alert", “Opening…” sets aria-busy.
  6. Phone → 320 px wide fits; 100dvh and safe-area insets; short landscape hides the cup.
  7. Dark mode → the app is light-only until #57, so the page declares color-scheme: light rather than half-turn.
  8. Reduced motion → no coin drops or steam, a still cup.
  9. Slow fonts or network → system font first, the cup is inline SVG, nothing blocks the first paint.
  10. Back after signing in → the page is no-store and lands on rule 1 (already signed in), so no stale form.

Wait screen and games

  1. Fast load (< 250 ms) → no loader at all. Once shown, it stays 600 ms.
  2. No true progress exists, so no percentage and no fake bar. A loop and honest lines.
  3. The game is offered, never forced (3 s); it never auto-plays or takes focus; Tab and Esc leave it.
  4. Data lands mid-game → instant swap, best score saved, nothing blocks.
  5. Fails mid-game → game stops, error card. Times out → game keeps going, the retry bar appears.
  6. Tab in the background → game and animation pause; nothing runs while hidden.
  7. Keys only on the game → arrow keys and space steer it only while it has focus, so page scroll and the sidebar's shortcuts are untouched.
  8. Touch → vertical swipes still scroll the page (touch-action: pan-y); Hop is a tap.
  9. Reduced motion → the cup stops and the lines still change; the game is still there but only if he taps Play.
  10. Screen readers → one polite “Loading your money”, then “Ready” or the error. The canvas is labelled optional.
  11. Private windows → localStorage can throw; the game works, the best score just isn't kept. Nothing is sent anywhere.
  12. No data in it → no figures, account names or card names on the wait screen.
  13. Before script loads → the cup is plain server HTML and CSS. The game's code is fetched only when he taps Play, so normal loads pay nothing.
  14. Back and forward → same wait screen, content area only; the sidebar links answer instantly.
  15. Battery → ≤ 60 fps, pixel ratio capped at 2, loop stops on leaving. Print → hidden.
  16. Offline mid-load → the “can't reach Sheets” card, which retries when online returns.
